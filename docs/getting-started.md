# Getting started

## Use an existing pack

1. Read its seller briefing and stated boundaries.
2. Run discovery with the people who request, execute, approve, and receive the service.
3. Replace illustrative process and metric examples with customer facts.
4. Decide whether the use case is qualified before adapting the demo.
5. Agree on proof measures and decision rules before a POV.

## Create a new pack

1. Copy templates/proof-pack into use-cases/your-use-case.
2. Choose a lowercase, hyphenated ID.
3. Complete every required artifact.
4. Reference shared capabilities in the machine-readable manifest.
5. Add the use case to catalog.yaml and shortlinks.yaml.
6. Run make validate, make test, and make syntax.
7. Obtain owner and governance review.

## Adapt the demo safely

Use the sample in simulation mode first. Replace adapters one at a time:

1. request and approval;
2. inventory and content source;
3. application quiesce and restore;
4. update execution;
5. validation;
6. ITSM and CMDB evidence.

Do not enable live changes until the customer has approved scope, credentials, pilot, failure handling, and recovery.
