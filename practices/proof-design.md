# Proof design

## Purpose

Design a small, credible test that produces enough evidence for a customer decision.

## Proof canvas

| Element | Prompt |
|---|---|
| Decision | What will the sponsor decide after the proof? |
| Hypothesis | If we change X, Y will improve because Z |
| Baseline | What comparable observation exists today? |
| Intervention | What exact workflow and version will run? |
| Population | Which services, hosts, windows, and exclusions apply? |
| Measures | Outcome, flow, quality, reliability, effort, and adoption |
| Evidence | Which systems produce each observation? |
| Guardrails | What must not get worse? |
| Decision rule | What result means proceed, adapt, or stop? |
| Cost | Build, run, integration, and maintenance effort |

## Design rules

- Agree on metric definitions before the POV.
- Use matched windows or comparable cohorts where possible.
- Report sample size and exclusions.
- Separate recovered capacity from realized cash savings.
- Include implementation and maintenance effort.
- Record adverse results and failure-path evidence.
- Avoid universal percentage promises.
